# Adversarial Spreadsheet Harness — Implementation Plan v5

**Design principles:**
- No custom check scripts. The only code is the dump step.
- Dumb dump, smart Evaluator. Dump everything flat and grepable. Evaluator searches what it needs.
- The harness knows it's for financial modeling. But model-specific detail (what sheets, what checks, what conventions) lives in files, not hardcoded in prompts.
- Per Vercel: fewer tools, more model autonomy.
- Per Anthropic: separate generation from evaluation. Context reset between them.

---

## Architecture

```
harness/
├── AGENTS.md              # Generated by Planner, ~100 lines, table of contents
├── conventions.md          # Seeded once, grows over time, shared across projects
├── model_spec.json         # Generated per-project by Planner from user brief
├── progress.txt            # Append-only session log
├── models/                 # Git-versioned .xlsx outputs
├── evals/                  # Dump output (regenerated each sprint)
│   ├── values/             # One .txt per sheet (calculated values as text tables)
│   ├── formulas/           # One .txt per sheet (one line per cell: coordinate + content)
│   └── screenshots/        # One .png per sheet
└── dump.py                 # The only script (~35 lines)
```

## The only script: dump.py

```
1. libreoffice --headless --calc model.xlsx        (recalculate so values are fresh)
2. pandas: read each sheet → to_string() → evals/values/{sheet}.txt
3. openpyxl: read each cell → "A4: =B4*(1+Assumptions!$B$3)" → evals/formulas/{sheet}.txt
4. libreoffice --headless --convert-to png → evals/screenshots/{sheet}.png
```

~35 lines. No evaluation logic. No domain knowledge.

## Agents

**Planner**
- Input: user brief (1-2 sentences) + conventions.md + optional existing .xlsx
- Output: model_spec.json + AGENTS.md
- For new models: generates spec from brief
- For edits: runs dump.py on existing file first, reverse-engineers structure, then generates spec for the change
- Runs once per project (or when user changes scope)

**Generator**
- Input: AGENTS.md, model_spec.json, conventions.md, sprint contract, current model.xlsx
- Builds one sprint at a time using openpyxl
- Saves to models/model.xlsx, git commits
- Sprint contract (from Planner) defines what "done" means — this is the primary defense against shortcuts

**Evaluator**
- Separate agent, fresh context, has tool access (bash, grep, read)
- Input: evals/ directory, sprint contract, conventions.md, screenshots
- NOT given dump as inline context — browses it with grep/cat like a human would
- Prompt: "You are a senior financial analyst reviewing a model built by a junior. You have data in evals/values/, formulas in evals/formulas/, screenshots in evals/screenshots/. You also have the sprint contract and conventions. Use grep, cat, and your judgment. Be adversarial. What would you flag before this goes to the partner?"
- Returns: PASS/FAIL + specific findings with cell references
- Only most recent failure feedback goes back to Generator on retry (not accumulated history)

## The loop

```
Planner generates spec from brief
for each sprint in spec:
    Generator builds sprint
    dump.py
    Evaluator browses dump
    if FAIL (max 3 retries):
        most recent feedback → Generator (context reset)
    if PASS:
        git commit
        append to progress.txt
        next sprint
after all sprints:
    holistic evaluation (Evaluator gets full dump, all sheets)
```

## Breakpoints we've identified and resolved

**Calculated values:** dump.py runs libreoffice --calc before pandas reads. One line. Values are fresh.

**Feedback thrashing:** Only most recent failure goes to Generator on retry. Full history in progress.txt for human reference.

**Editing external models:** Planner runs dump.py on the existing file to understand structure before generating spec. No VBA/macros to worry about (formula-only models).

**LibreOffice vs Excel rendering:** conventions.md should specify formatting that renders well in both (standard fonts, explicit widths). Not perfect but reduces the gap.

**Rate limits:** Progress is saved after every passing sprint. If rate-limited mid-loop, resume from progress.txt next session. This is Phase 3's session resumption — needed from day 1.

## Phased build

### Phase 0 (Day 1): Single sprint, end-to-end
- Scaffold the file structure
- Write dump.py
- Write Planner, Generator, Evaluator prompts
- Wire the loop for one sprint
- input/ directory for ingesting arbitrary materials (xlsx, csv, txt, images)
- Edit mode: Planner browses existing model dump, plans targeted sprints
- Success: brief → one sheet → evaluated → progress.txt + git

### Phase 1 (Days 2-3): Multi-sprint loop
- Sprint contracts from Planner
- Sequential sprints with per-sprint eval
- Holistic final evaluation
- Retry + rollback logic
- Success: brief → complete multi-sheet model → all sprints pass + holistic review

### Phase 2 (Days 4-5): Evaluator calibration
- Build test models with planted errors
- Run Evaluator against them, refine prompt until it catches everything
- Tune the grading rubric in conventions.md (not in agent prompts)
- Success: Evaluator catches all planted defects

### Phase 3 (Days 6-7): Multi-session memory
- Session initialization protocol (read AGENTS.md → progress.txt → spec → git log)
- Conventions learning after project completion (what did user correct? what did Evaluator flag?)
- Template reuse (successful specs become starting points for new projects)
- Success: resume days later without regression

### Phase 4 (Week 2+): Edit existing models
- Planner ingestion mode (dump existing xlsx, understand structure)
- Targeted sprints (edit specific sheets rather than build from scratch)
- Success: hand it someone else's model, describe the change, get it done
